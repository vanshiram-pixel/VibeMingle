# V4.1 — Explicit match consent and age eligibility

## Enforcement added
- Queue entry now requires an explicit, versioned user consent record.
- Disabling consent immediately removes that user's waiting queue row.
- Queue entry requires trusted age-verification eligibility; clients cannot self-assert adulthood.
- Verification writes are service-role-only and require method plus a hashed evidence reference.
- Queue consent timestamp is copied from the recorded user action, not generated by queue entry.
- Eligibility revocation removes queued users.

## Integration gates (not yet claimed complete)
- Integrate a legally suitable age-verification provider/review process and its server callback.
- Build consent UI, clear explanation, versioning, and withdrawal action.
- Apply migration in a controlled staging database and test negative/positive paths.
- Keep age evidence and DOB private; never expose proof/reference hash to clients.
