## Existing messaging implementation (source observed)
The one Dart file defines:
- `MessagingScreen`: reads `conversation_members` and `conversations`; opens a friend conversation through RPC `conversation_open`; navigates to `ConversationScreen`.
- `ConversationScreen`: loads `messages`, subscribes to Postgres changes filtered by conversation, marks conversations read via `conversation_mark_read`, sends through `message_send`, edits through `message_edit`, deletes through `message_delete`, and reports through `message_report`.
- UI: conversation list, new-chat dialog accepting a friend UUID, message bubbles, composer/send, long-press edit/delete for own messages and report for other messages.

## Risks / gaps observed from source
1. `auth.currentUser!` is force-unwrapped in loading/build paths; signed-out/expired sessions can crash.
2. New chat asks the user to manually enter a UUID; no friend picker/search/contact flow is implemented here.
3. Message query selects `body` plaintext; this is not an E2EE client implementation. Do not describe it as end-to-end encrypted.
4. Realtime callback triggers an uncoalesced full reload; potential overlapping requests and excess DB traffic.
5. `_load()` sets loading false in finally but does not set loading true on refresh; error UI is snack-bar only and may retain stale content.
6. `_report()` reports a message only; no conversation/user report flow shown.
7. No visible pagination, retry control, optimistic send, attachment, typing/presence, reactions, delivery/read receipt UI, call initiation/request, or conversation profile/block controls in this file.
8. RPC/table definitions, membership enforcement, RLS, validation, rate limits, encryption, and authorization cannot be verified because schema/backend migrations are absent.
9. No package manifest or app entrypoint exists; this file alone cannot be built/tested as a Flutter application in this repository snapshot.
